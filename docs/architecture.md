# Архитектура NazarovGroup

Публичный трафик приходит в Nginx. Запросы к `/api/*` направляются в FastAPI, остальные — в Next.js. PostgreSQL и bot доступны только во внутренней Docker-сети.

## Границы компонентов

- `frontend` отвечает за публичный UI, SEO, client-side validation и вызовы API.
- `backend` владеет бизнес-правилами, транзакциями, persistence и интеграциями.
- `bot` — отдельный процесс доставки Telegram-уведомлений; он не должен содержать booking-логику.
- `postgres` хранит управляемый контент, записи, очередь уведомлений и будущие платёжные сущности.
- `nginx` завершает публичный HTTP-трафик, добавляет базовые headers и rate limit для API.

## Реализованный контур записи

1. `GET /api/bookings/availability` возвращает свободные целые часы в пределах рабочего окна. Длительность выбранных услуг на календарь не влияет.
2. `POST /api/bookings` принимает одну или несколько услуг, берёт PostgreSQL advisory lock на дату, повторно проверяет выбранный час и сохраняет первичный осмотр. Частичный уникальный индекс не допускает две активные записи на одинаковые дату и время.
3. В той же транзакции создаётся `notification_outbox`; background worker доставляет событие внутреннему bot endpoint с shared secret.
4. Bot валидирует событие и отправляет сообщение в настроенный Telegram-чат. Неудачные доставки повторяются, поэтому заявка не зависит от доступности Telegram в момент записи.
5. Защищённая admin-сессия позволяет менять контент и рабочий статус первичного осмотра.

## План расширения

1. Добавить рабочие посты/мастеров для параллельных записей.
2. Ввести payment entity, idempotency keys и webhook ЮKassa.
3. Перед многопользовательской админкой добавить пользователей, роли, отзыв сессий и audit log.
